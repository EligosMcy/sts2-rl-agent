# 杀戮尖塔2 生命值（HP）存储与同步机制

> 目标读者：想要在自己的实现（无头模拟器 / 复刻引擎 / Mod）里**一比一复刻 STS2 血量系统**的人。
> 本文只对照原版源码：`decompiled/MegaCrit.Sts2.*`（Godot + C# 反编译代码），所有行号均指向仓库内 `decompiled/` 下的文件。
>
> 阅读建议：先看 §1 核心结论，再按 §2(存储) → §4(数据) → §6(HUD) 理解三层结构，最后看 §8 的「增加最大生命值」语义推导。

## 1. 核心结论（TL;DR）

| 结论 | 说明 |
|---|---|
| **唯一数据源** | 内存中的 `Creature` 实例（玩家的就是 `Player.Creature`）。`_currentHp` / `_maxHp` 是私有的，只能通过命令层写入 |
| 存档不是数据源 | `SerializablePlayer.CurrentHp/MaxHp` 只是 `Creature` 的**序列化快照**，方向永远是 `Creature → 存档` |
| 场景节点不存数据 | `NCreature` 只持有 `Entity`（同一个 `Creature` 引用），不复制血量 |
| HUD 只读不写 | 战斗血条靠「状态变化时重新拉取」，顶栏血条靠「订阅 HP 事件」，两者都直接读 `Creature` |
| 增加最大生命值会同步加血 | `GainMaxHp` = 提上限 + 回等量血，所以 **`77/80` 上限 +10 → `87/90`**（不是 `77/90`） |
| 降低最大生命值不会加血 | `LoseMaxHp` 先扣掉超出新上限的部分再降上限，`77/80` 上限 -10 → `70/70` |

数据流向：

```
                       ┌──────────────────────────────┐
   CreatureCmd ──────► │  Creature（唯一数据源）        │
   Damage / Heal       │  _currentHp / _maxHp / _block │
   GainMaxHp ...       └───────────────┬──────────────┘
                                       │
        ┌──────────────────────────────┼───────────────────────────────┐
        │                              │                               │
        ▼                              ▼                               ▼
  NTopBarHp                  NCreature（场景节点）           SerializablePlayer
  （订阅 HP 事件）            └─ NCreatureStateDisplay         （存档快照）
                                     └─ NHealthBar
                                        （状态变化时刷新）
```

## 8. 最大生命值变更语义（重点）

### 8.1 `GainMaxHp` = 提上限 + 回等量血

[CreatureCmd.cs#L569-L582](file:///c:/Project/sts2-rl-agent/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs#L569-L582)

```csharp
public static async Task GainMaxHp(Creature creature, decimal amount)
{
    if (amount < 0m) throw new ArgumentException(...);
    await SetMaxHp(creature, (decimal)creature.MaxHp + amount);   // ① 先提上限
    // ...记录 MaxHpGained 统计...
    await Heal(creature, amount);                                 // ② 再回等量血
}
```

以 **`77/80`，`amount = 10`** 为例逐步推导：

| 步骤 | 调用 | 计算 | 结果 |
|---|---|---|---|
| 起始 | — | — | `77/80` |
| ① | `SetMaxHp(90)` → `SetMaxHpInternal(90)` | `MaxHp = 90`；`CurrentHp = min(77, 90)` | `77/90` |
| ② | `Heal(10)` → `HealInternal(10)` → `SetCurrentHpInternal(87)` | `CurrentHp = min(77 + 10, 90)` | **`87/90`** |

**结论：`77/80` + 上限 10 = `87/90`。**

推论：

- **满血时增加上限仍满血**：`80/80` +10 → `SetMaxHp` 得 `80/90` → `Heal(10)` 得 `90/90`。
- 若 `amount` 大于缺口，只是回满，不会溢出（`Heal` 内部夹到 `MaxHp`）。
- 若治疗被削减，则可能停在 `77/90`：`Heal` 会先过 [`Hook.ModifyHealAmount`](file:///c:/Project/sts2-rl-agent/decompiled/MegaCrit.Sts2.Core.Hooks/Hook.cs#L1253-L1261)，其默认实现是原样返回（[AbstractModel.cs#L681-L684](file:///c:/Project/sts2-rl-agent/decompiled/MegaCrit.Sts2.Core.Models/AbstractModel.cs#L681-L684)），当前反编译集中没有遗物/状态覆盖它，所以正常就是 `87/90`。

### 8.2 `LoseMaxHp` = 先削血、再降上限

[CreatureCmd.cs#L584-L601](file:///c:/Project/sts2-rl-agent/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs#L584-L601)

```csharp
decimal newMax = creature.MaxHp - amount;
if (newMax < creature.CurrentHp)
    await Damage(choiceContext, creature, creature.CurrentHp - newMax, Unblockable | Unpowered [| Move], null, null);

```

`77/80` 上限 -10：`newMax = 70 < 77`，先扣 7 点血 → `70/70`，再降上限 → **`70/70`**。当前血绝不会被抬高。

## 9. 复刻 / 对接要点

1. **只维护一份血量状态**：模拟器里应把 `(max_hp, current_hp, block)` 放在一处（对应 `Creature`），存档、网络包、UI 全部作为读方，避免多处副本不同步。
2. **写入必须走命令层**：所有变更集中到 `Damage / Heal / SetCurrentHp / GainMaxHp / LoseMaxHp / SetMaxHp`，并保证 `SetCurrentHpInternal` 夹上限、`SetMaxHpInternal` 只夹不补这两个不变式。
3. **`GainMaxHp` 别漏掉 `Heal(amount)`**：这是最容易做错的点，漏掉就会得到 `77/90` 而不是 `87/90`；反过来 `LoseMaxHp` 别顺手补血。
4. **`Heal` 要过 Hook**：治疗量先经 `ModifyHealAmount` 再夹上限，否则未来接入削减治疗的遗物/状态时会不一致。
5. **上限变化要联动三处**：`_maxHp` 变化会同时影响血条长度（`GetFgWidth`）和文本 `current/max`，所以任何上限变更都应触发一次 UI 刷新。
6. **死亡判定**：`IsAlive = CurrentHp > 0`；死亡由 `Kill` 把血打到 0 后统一处理（[CreatureCmd.cs#L325-L409](file:///c:/Project/sts2-rl-agent/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs#L325-L409)），`MaxHp <= 0` 也会直接触发死亡。
7. **多人**：以主机 `Creature` 为权威，客户端用 `NetFullCombatState.CreatureState{currentHp, maxHp}` 覆盖，不要在客户端本地独立演化血量。
