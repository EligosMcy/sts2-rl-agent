# 杀戮尖塔 2 卡牌与遗物池管理机制

本文总结反编译源码（`decompiled/`）中「卡牌 / 遗物」的池化数据结构，以及商店、战斗奖励、宝箱等场景如何按正确的池与稀有度进行随机抽取，并重点说明遗物如何避免重复抽取。

所有行号均指向仓库内 `decompiled/` 下的文件。

---

## 1. 总览

游戏把「内容」抽象成三层：

| 层 | 类型 | 作用 |
| --- | --- | --- |
| 内容模型 | `AbstractModel` 子类（`CardModel` / `RelicModel` / `PotionModel` ...） | 单个卡牌 / 遗物的静态定义（稀有度、类型、效果） |
| 内容池 | `CardPoolModel` / `RelicPoolModel` / `PotionPoolModel` | 按来源（角色 / 无色 / 事件 / 状态 / 诅咒…）组织一批模型 |
| 注册表 | `ModelDb` | 全局 `ModelId -> 规范实例` 字典，所有池与模型都从这里取 |

抽取流程统一是：**先确定用哪个池 -> 按稀有度权重 roll 出稀有度 -> 在该池里筛出对应稀有度的候选 -> 用对应的 Rng 随机取一个**。

## 2. 模型层数据结构

### 2.1 ModelDb：全局内容注册表

`MegaCrit.Sts2.Core.Models.ModelDb`（`MegaCrit.Sts2.Core.Models/ModelDb.cs`）


- `Init()`（L234-L243）在启动时反射扫描 `AbstractModel` 的所有子类，为每个类型 `new` 一个实例并存入字典。
- `ModelId` = `category + entry`（L300-L323），category 取抽象基类名 slug 化（如 `card`、`relic`），entry 取具体类名 slug 化，例如 `ModelId(card, bash)`。
- 各种便捷访问器：`ModelDb.Card<T>()`、`ModelDb.Relic<T>()`、`ModelDb.CardPool<T>()`、`ModelDb.RelicPool<T>()`、`GetById<T>(id)`。
- 池的聚合：

  - `AllCardPools`（L73）= 角色卡池 + 共享卡池。
  - `AllRelics`（L151）= 所有遗物池的遗物。
  - `AllRelicPools`（L155）= 角色遗物池 + 共享遗物池。

### 2.2 AbstractModel：规范实例 vs 可变实例

`MegaCrit.Sts2.Core.Models/AbstractModel.cs`

```csharp
public ModelId Id { get; }
public bool IsMutable { get; private set; }
public bool IsCanonical => !IsMutable;      // L35
```

- **规范实例（Canonical）**：ModelDb 中那份，全局唯一、只读。`AssertCanonical()` / `AssertMutable()` 用于约束。
- **可变实例（Mutable）**：进入玩家卡组 / 遗物栏 / 商店槽位时用 `MutableClone()`（L102-L109）克隆一份，可独立记录升级、层数、使用次数等状态。
- 典型用法：`ModelDb.Relic<T>().ToMutable()`、`relic.AssertMutable()`（`RelicCmd.Obtain`）。
- 比较「是不是同一张卡 / 同一个遗物」时统一用 `CanonicalInstance` 或 `Id`，而不是引用比较。

## 3. 卡牌池

### 3.1 CardPoolModel

`MegaCrit.Sts2.Core.Models/CardPoolModel.cs`

```csharp
public abstract class CardPoolModel : AbstractModel, IPoolModel
{

    private HashSet<ModelId>? _allCardIds;

    public IEnumerable<CardModel> AllCards { get; }  // L34-L45
    // GenerateAllCards() -> ModHelper.ConcatModelsFromMods() 拼接模组内容

    public abstract bool IsColorless { get; }
    public abstract string Title { get; }
    protected abstract CardModel[] GenerateAllCards();               // 子类硬编码枚举

                                                   CardMultiplayerConstraint multiplayerConstraint); // L55
```

要点：
- 池内容由子类 `GenerateAllCards()` **硬编码**成数组（不是配置文件），例如 `IroncladCardPool.GenerateAllCards()` 列出 87 张铁甲战士牌。
- `AllCards` 缓存到 `_allCards`，且会拼接模组新增卡。
- `GetUnlockedCards` 做两道过滤：
  1. `FilterThroughEpochs`：未揭示的 Epoch（成就解锁阶段）对应的卡被移除（如 `Ironclad2Epoch / Ironclad5Epoch / Ironclad7Epoch`）。
  2. 联机约束：单机时移除 `MultiplayerOnly` 卡，联机时移除 `SingleplayerOnly` 卡。

## 5. 随机数体系（可复现的关键）

游戏按「用途」拆分 Rng 流，避免一种抽取影响另一种：

- `MegaCrit.Sts2.Core.Random/PlayerRngSet.cs`：每名玩家持有 `Rewards` / `Shops` / `Transformations` 等多条流（`Dictionary<PlayerRngType, Rng>`），均从 `seed + 用途名` 派生。
- `MegaCrit.Sts2.Core.Runs/RunRngSet.cs`：局内流，如 `RunState.Rng.UpFront` 用于遗物抓取袋的洗牌。

因此：
- **商店卡牌 / 遗物 / 药水价格抖动**用 `player.PlayerRng.Shops`。
- **战斗奖励卡牌、遗物稀有度、升级 roll**用 `player.PlayerRng.Rewards`。
- 存档时保存每条流的 `Counter`，读档后 `FastForwardCounter` 重放到相同位置（`PlayerRngSet.cs:L37-L63`）。

### 6.4 商店单张卡的抽取算法

`MegaCrit.Sts2.Core.Factories/CardFactory.cs:L32-L56`

```csharp
public static CardCreationResult CreateForMerchant(Player player, IEnumerable<CardModel> options, CardType type)
{
    options = Hook.ModifyMerchantCardPool(player.RunState, player, options);      // 遗物可改池
    options = options.Where(c => c.Rarity != CardRarity.Basic);
    options = FilterForPlayerCount(player.RunState, options);

    CardModel[] source = options.ToArray();
    CardRarity rolledRarity = Hook.ModifyMerchantCardRarity(player.RunState, player,
        player.PlayerOdds.CardRarity.RollWithoutChangingFutureOdds(CardRarityOddsType.Shop)); // 商店不影响后续概率

    List<CardModel> list = source.Where(c => c.Rarity == rolledRarity && c.Type == type).ToList();
    while (list.Count == 0) {                 // 该稀有度+类型无候选时逐级升稀有度
        rolledRarity = rolledRarity.GetNextHighestRarity();
        if (rolledRarity == CardRarity.None) throw ...;
        list = source.Where(c => c.Rarity == rolledRarity && c.Type == type).ToList();
    }
    CardModel cardModel = player.RunState.CreateCard(player.PlayerRng.Shops.NextItem(list), player);
    RollForUpgrade(player, cardModel, -999999999m);   // 商店牌不升级
    return new CardCreationResult(cardModel);
}
```

要点：
- 稀有度用 **Shop 权重** roll，且 `RollWithoutChangingFutureOdds` 不污染后续战斗奖励的稀有度累积。
- 用 `PlayerRng.Shops.NextItem` 选中具体卡。
- `-999999999m` 的升级基础概率 = 永远不升级。
- 有稀有度重载版本（L58-L69），用于无色卡这类**固定稀有度**的槽位。

### 7.2 卡牌奖励抽取算法

`MegaCrit.Sts2.Core.Factories/CardFactory.cs:L163-L191` `CreateForReward`

```csharp
options = Hook.ModifyCardRewardCreationOptions(player.RunState, player, options);
IEnumerable<CardModel> options2 = options.GetPossibleCards(player).Except(blacklist).ToList();
options2 = FilterForPlayerCount(player.RunState, options2);

if (options.RarityOdds == CardRarityOddsType.Uniform)
    items = options2.Where(c => c.Rarity != Basic && c.Rarity != Ancient);
else {
    var allowedRarities = options2.Select(c => c.Rarity).ToHashSet();
    selectedRarity = RollForRarity(player, options.RarityOdds, options.Source, allowedRarities, ...);
    items = options2.Where(c => c.Rarity == selectedRarity);
}
Rng rng = options.RngOverride ?? player.PlayerRng.Rewards;
CardModel cardModel = rng.NextItem(items);      // Rewards 流选具体卡
```

- `GetPossibleCards`（`CardCreationOptions.cs:L93-L103`）= 所有指定卡池的 `GetUnlockedCards`，再套 `CardPoolFilter`。
- 多张奖励之间通过 `blacklist` 累积（`CardFactory.cs:L71-L91`），保证**同一组 3 张不重复**。
- 选完卡后做升级 roll（L80-L84，`RollForUpgrade(player, cardModel, 0m, rng)`），基础概率 0，非 Rare 卡每推进 1 层 +0.01（`Scarcity` 难度 +0.005），封顶不设。

### 7.3 稀有度概率与「保底累积」

`MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs`

基础权重按 `CardRarityOddsType` 分支（L102-L143）：

| 类型 | Common | Uncommon | Rare |
| --- | --- | --- | --- |
| RegularEncounter | 0.60（Scarcity 0.615） | 0.37 | 0.03（Scarcity 0.0149） |
| EliteEncounter | 0.50（Scarcity 0.549） | 0.40 | 0.10（Scarcity 0.05） |
| BossEncounter | 0 | 0 | 1.00 |
| Shop | 0.54（Scarcity 0.585） | 0.37 | 0.09（Scarcity 0.045） |
| Uniform | 0.33 | 0.33 | 0.33 |

关键设计（L53-L65）：

```csharp
public CardRarity Roll(CardRarityOddsType type) {
    var r = RollWithoutChangingFutureOdds(type, (type == BossEncounter) ? 0f : CurrentValue);
    if (r == Rare) CurrentValue = -0.05f;                       // 出了 Rare 就重置
    else CurrentValue = Math.Min(CurrentValue + RarityGrowth, 0.4f);  // 否则累积 +0.01
    return r;
}
```

- 这就是「打怪越多越容易出稀有」的保底机制：`CurrentValue` 从 `-0.05` 出发，每次没出 Rare 就 +`RarityGrowth`，上限 `0.4`。
- 只有 **Encounter 来源**（Monster / Elite / Boss）才走会累积的 `Roll()`；否则走 `RollWithBaseOdds`（`CardFactory.RollForRarity`，L193-L214）。
- **商店 / 事件等不累积**：`RollWithoutChangingFutureOdds`（`CardFactory.cs:L42`）只读当前值不写回。

### 7.4 遗物奖励

`MegaCrit.Sts2.Core.Rewards/RelicReward.cs`

```csharp
protected override RewardType RewardType => RewardType.Relic;
public override int RewardsSetIndex => 3;       // 奖励栏排序权重

public override Task Populate() {
    if (_relic != null) return Task.CompletedTask;
    if (_rarity == RelicRarity.None)
        _relic = (_rngOverride != null
            ? RelicFactory.PullNextRelicFromFront(Player, _rngOverride)

```

- 奖励遗物走的是抓取袋**头部**（`PullFromFront`），与商店的尾部（`PullFromBack`）区分，保证两条路径取到的分布不同、且不会互相「撞车」。

## 8. 遗物如何避免重复抽取（核心）

### 8.1 RelicGrabBag 的数据结构

`MegaCrit.Sts2.Core.Runs/RelicGrabBag.cs`

```csharp
private static readonly HashSet<RelicRarity> _rarities =
    { RelicRarity.Common, RelicRarity.Uncommon, RelicRarity.Rare, RelicRarity.Shop };

private readonly Dictionary<RelicRarity, List<RelicModel>> _deques = new();  // 按稀有度分桶的「牌堆」
private readonly List<RelicModel> _mpFallbackDequeue = new();               // 联机兜底
private readonly bool _refreshAllowed;                                      // 桶空时是否重置
private List<RelicModel>? _originalRelics;                                  // 原始全集（用于刷新）
```

- 本质是**按稀有度分成 4 个队列（deque 用 List 模拟）**，每个队列在开局洗好牌。
- 只有 Common / Uncommon / Rare / Shop 四种稀有度进入抓取袋；Starter / Event / Ancient 等不进池。
- 取一个就从队列里**移除**一个 → 天然不重复。

### 8.2 填充（Populate）

`Populate(Player, Rng)`（L56-L79）：

```csharp
List<RelicModel> list = ModelDb.RelicPool<SharedRelicPool>().GetUnlockedRelics(player.UnlockState).ToList();
list.AddRange(player.Character.RelicPool.GetUnlockedRelics(player.UnlockState));  // 共享池 + 角色池
list.RemoveAll(r => !_rarities.Contains(r.Rarity));                              // 只保留 4 种稀有度
_originalRelics = list;
foreach (var item in list) _deques[item.Rarity].Add(item);                       // 入桶
foreach (var d in _deques.Values) d.UnstableShuffle(rng);                        // 每桶洗牌
```

- 池 = **共享遗物池 + 当前角色专属遗物池**，经解锁过滤，只留 4 种稀有度。
- 洗牌用 `UnstableShuffle`（Fisher–Yates，`Extensions/ListExtensions.cs:L21-L36`）。
- `Populate` 有 `IsPopulated` 守卫（L58-L61），一局只填一次。

### 8.3 抽取 + 移除

```csharp
public RelicModel? PullFromFront(RelicRarity rarity, IRunState runState)   // L103-L126
{
    var deque = GetAvailableDeque(rarity);
    if (deque == null || deque.Count == 0) return null;
    var relic = deque[0];
    while (!relic.IsAllowed(runState)) {       // 跳过当前不满足条件的（如分幕限制）
        deque.RemoveAt(0);
        if (deque.Count == 0) {
            if (!_refreshAllowed) return null;
            RefreshRarity(rarity);
        }
        relic = deque[0];
    }
    deque.RemoveAt(0);                         // 取走 = 从池中永久移除
    return relic;
}

public RelicModel? PullFromBack(RelicRarity rarity, IEnumerable<RelicModel> blacklist, IRunState runState) // L128-L151
```

- 「取走即移除」，因此**同一个遗物在一局内不会被抽到第二次**。
- `PullFromBack` 用于商店，从队尾往前找第一个不在黑名单且 `IsAllowed` 的。

### 8.4 获得时再次清理（双保险）

`MegaCrit.Sts2.Core.Commands/RelicCmd.cs:L21-L41`

```csharp
public static async Task<RelicModel> Obtain(RelicModel relic, Player player, int index = -1)
{
    player.AddRelicInternal(relic, index);
    if (!relic.IsStackable)                       // 默认 false
    {
        player.RelicGrabBag.Remove(relic);        // 从个人抓取袋移除
        runState.SharedRelicGrabBag.Remove(relic);// 从共享抓取袋移除
    }
    ...
}
```

- 只要遗物不是 `IsStackable`，获得后立刻从**两个**抓取袋里剔除。
- 这覆盖了非抽取来源的获得（事件给遗物、遗物替换、`RelicCmd.Obtain` 直调等），保证后续任何抽取都不会再出现它。
- 一局内所有获得遗物的路径最终都经过 `RelicCmd.Obtain`（奖励 / 商店 / 事件 / 宝箱奖励落袋）。

### 8.5 池抽空后的行为：FallbackRelic

`MegaCrit.Sts2.Core.Factories/RelicFactory.cs:L14-L43`

```csharp
private static RelicModel FallbackRelic => ModelDb.Relic<Circlet>();

public static RelicModel PullNextRelicFromFront(Player player, RelicRarity rarity) {
    var relic = TestRngInjector.ConsumeRelicOverride()
             ?? player.RelicGrabBag.PullFromFront(rarity, player.RunState)
             ?? FallbackRelic;                       // 抽不出来就用兜底
    player.RunState.SharedRelicGrabBag.Remove(relic);
    return relic;
}
```

- 池子抽空后不会重复给已有的遗物，而是给**兜底遗物 `Circlet`**（原版里那个「+1 空位/无属性」的填充遗物）。
- 抽取时还会顺手从共享抓取袋里删除该遗物（L29 / L41），避免联机其他玩家再抽到。

### 8.6 个人袋 vs 共享袋：`_refreshAllowed` 的差异

| 抓取袋 | 创建处 | `refreshAllowed` | 抽空行为 |
| --- | --- | --- | --- |
| 玩家个人袋 `Player.RelicGrabBag` | `Player.CreateForNewRun`（`Player.cs:L208`） `new RelicGrabBag()` | `false` | 该稀有度队列空了 → 逐级降稀有度（Shop→Common→Uncommon→Rare）→ 实在没有 → `null` → `Circlet` |
| 局共享袋 `RunState.SharedRelicGrabBag` | `RunState`（`Runs/RunState.cs:L138/L170`） `new RelicGrabBag(refreshAllowed: true)` | `true` | 队列空了会 `RefreshRarity` 用 `_originalRelics` 重新灌满并再次洗牌 |

- **个人袋不刷新**：这是单机「遗物不重复」的根本保证。
- **共享袋会刷新**：主要给联机宝箱用（`Multiplayer.Game/TreasureRoomRelicSynchronizer.cs`）。宝箱每个玩家各抽一件共享袋里的遗物（L71-L81 `_sharedGrabBag.PullFromFront(rarity, runState)`），抽空后允许重置，避免联机因池子耗尽而拿不到东西。
- 降级链（`GetAvailableDeque`，L192-L215）：`Shop -> Common -> Uncommon -> Rare -> None`；再不行才用 `_mpFallbackDequeue`。

### 8.7 重复遗物的兜底处理（联机/宝箱）

- `NTreasureRoomRelicCollection.cs:L396` 里，当出现重复时调用 `player.RelicGrabBag.MoveToFallback(result.relic)`（`RelicGrabBag.cs:L167-L190`）——把该遗物从所有稀有度桶中移除并放进 `_mpFallbackDequeue`，避免后续再被抽到。
- `SealedDeck / Draft / Insanity / DeadlyEvents` 等 Modifier 会主动 `RelicGrabBag.Remove<T>()` + `SharedRelicGrabBag.Remove<T>()`（如 `Modifiers/SealedDeck.cs:L42-L44`）来屏蔽特定遗物。

### 8.8 存档与网络同步

- `RelicGrabBag.ToSerializable()`（L217-L229）把每个稀有度桶的 `List<ModelId>` 存下来；`FromSerializable` / `LoadFromSerializable`（L231-L257）读回并重建队列。
- 因此**读档后剩余的可抽遗物集合与顺序完全一致**，不会因为读档而重复抽到已有的遗物。
- 联机时 `CombatStateSynchronizer` / `SyncRngMessage` 也会同步 `SerializableRelicGrabBag`（`SyncRngMessage.cs:L12`、`CombatStateSynchronizer.cs:L116`）。

### 8.9 一句话总结遗物去重

> 遗物用「按稀有度分桶的、开局洗好的抓取袋（`RelicGrabBag`）」管理；**抽取 = 从桶里移除**，**获得 = 再从两个桶里各删一次**；桶空了给兜底 `Circlet` 而不是重复给已有遗物；只有联机共享袋才允许重置。

## 9. 卡牌 vs 遗物：去重行为对比

| 维度 | 卡牌 | 遗物 |
| --- | --- | --- |
| 全局池结构 | `CardPoolModel` 提供无状态候选列表，无抓取袋 | `RelicGrabBag` 按稀有度分桶的有状态队列 |
| 抽取后是否移除 | 否（同一张卡可反复出现在不同商店 / 奖励） | 是（抽走即移除） |
| 局部去重 | 同一组奖励内用 `blacklist` 排除（`CardFactory.cs:L166`）；同一家店用 `Except(second)` 排除（`MerchantCardEntry.cs:L68-L71`） | 桶本身就是去重；商店再叠加 `blacklist`（`MerchantRelicEntry.cs:L47`） |
| 池耗尽行为 | 不会耗尽（池是无限候选集） | 个人袋耗尽 → 兜底 `Circlet`；共享袋耗尽 → 重置 |
| 稀有度决定方式 | 每次抽取时按权重 roll（`CardRarityOdds`，可累积保底） | 先 roll 稀有度（`RelicFactory.RollRarity`），再从对应桶取 |
| 随机数流 | `PlayerRng.Rewards`（奖励）/ `PlayerRng.Shops`（商店） | 个人遗物用 `PlayerRng.Rewards` 决定稀有度，具体遗物由袋中顺序决定；共享袋用 `State.Rng.UpFront` 洗牌 |

## 10. 抽取流程图（简化）

```
商店：
  MerchantInventory.CreateForNormalMerchant(player)
    ├─ 角色牌 x5 : 角色CardPool.GetUnlockedCards
    │              -> CardFactory.CreateForMerchant(type, ShopRarityOdds, Shops rng)
    ├─ 无色牌 x2 : ColorlessCardPool，固定 Uncommon/Rare
    ├─ 遗物   x3 : RelicFactory.RollRarity()/Shop
    │              -> RelicGrabBag.PullFromBack(rarity, blacklist)   [从袋尾取并移除]
    └─ 药水   x3 : PotionFactory

战斗奖励：
  RewardsCmd.OfferForRoomEnd(player, room)
    -> RewardsSet.WithRewardsFromRoom(room)
       -> GenerateRewardsFor(room)
          ├─ 金币
          ├─ 药水(概率)
          ├─ CardReward(options=CardCreationOptions.ForRoom(...), 3)
          │    -> CardFactory.CreateForReward -> 稀有度 roll -> RewardsRng 选卡（组内不重复）
          └─ Elite 额外 RelicReward
               -> RelicFactory.PullNextRelicFromFront(player)
               -> RelicGrabBag.PullFromFront(rarity)  [从袋头取并移除]

宝箱(联机)：
  TreasureRoomRelicSynchronizer.BeginRelicPicking()
    -> SharedRelicGrabBag.PullFromFront(rarity)   [共享袋，refreshAllowed=true]
```
